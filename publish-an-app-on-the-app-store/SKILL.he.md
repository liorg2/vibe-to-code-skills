# פרסמו את האפליקציה ב־Apple App Store

מאת Vibe to Dev (https://www.vibetodev.com/he). המדריך עם קישורים רשמיים: https://www.vibetodev.com/he/guides/publish-an-app-on-the-app-store
זמן: יום עבודה, ועוד הרשמה (1–14 ימים) ובדיקה לאישור (לרוב 1–2 ימים). עלות: 99 דולר לשנה עבור Apple Developer Program.

שמות המוצרים ב־skill הזה (ספקי אירוח, מסדי נתונים, תשלומים, אימייל, מעקב שגיאות וכלי AI) הם דוגמאות בלבד. קודם בדקו במה הפרויקט באמת משתמש, לפי הקוד, קובצי ההגדרות וקובצי החבילות, והתאימו כל שלב למה שקיים בו. אם שלב מזכיר כלי שהפרויקט לא משתמש בו, בצעו את השלב המקביל בכלי שבו כן משתמשים; אם המשתמשים עוד לא בחרו כלי, הציגו את האפשרויות ותנו להם לבחור. ה־skill הזה עובד בכל סוכן פיתוח ב־AI (Claude Code, Cursor, Codex, Copilot ואחרים). אם מוזכרת פקודה, תיקייה או קובץ של כלי מסוים, השתמשו במקבילה של הסוכן שלכם.

## Rules

- בדקו קודם, הסבירו בשפה פשוטה, שלב אחד בכל פעם. אל תעברו לשלב הבא עד שתנאי "Done when" של השלב הנוכחי מתקיים.
- לעולם אל תיצרו משאבים בתשלום, אל תעשו push, אל תפרסו ואל תגישו בלי לבקש אישור. המשתמשים מבצעים בעצמם כל פעולה בחשבון, כל תשלום וכל לחיצה סופית על פרסום.
- כל שלב מסומן:
  - 👤 YOU: רק המשתמשים יכולים לבצע זאת (חשבון, תשלום, אימות זהות או לוח בקרה). הסבירו והמתינו.
  - 🤖 AI: אתם מבצעים זאת בפרויקט, במסגרת הכללים שלמעלה.
  - 🤝 BOTH: אתם מכינים או בודקים; המשתמשים מבצעים את החלק של החשבון או הפרסום.
- בתיאורי השלבים הפנייה היא למשתמשים; בשורות "Task:" הכוונה ב־"אני" או "עליי" היא למשתמשים: דווחו להם.

## Redact

לעולם אל תדפיסו סוד, מפתח, סיסמה או טוקן. דווחו רק שמות משתנים, וכתבו `<REDACTED>` במקום כל ערך שצריך להציג.

## איך לדבר

- קצר, ידידותי ומקצועי. משפטים קצרים ומילים פשוטות. בלי מילות מילוי, בלי מחמאות ובלי לחזור על מה שהמשתמשים אמרו הרגע.
- בכל הודעה: מה מצאתם או עשיתם, ואז הדבר האחד שהמשתמשים צריכים לעשות או להחליט. פרטים רק אם ביקשו.
- שאלו רק מה שאי אפשר למצוא בפרויקט בעצמכם. שאלה אחת בכל פעם, עם הניחוש הטוב ביותר שלכם כתשובת ברירת מחדל.
- ענו על מה שנשאלתם, ועצרו.

## Start

עזרו לי להכין את אפליקציית Expo ל־App Store של Apple. עברו על הפרויקט ותגידו לי מה ה־bundle ID, הגרסה, ההרשאות, ה־API הרגישים לפרטיות, תהליכי החשבון, האייקונים והגדרות הבנייה, ואילו פערים מול דרישות הבדיקה אפשר לצפות. אל תירשמו, אל תשלמו, אל תעלו גרסת בנייה ואל תגישו דבר. ציינו נתיבי קבצים והפרידו בין עובדות מאומתות לשאלות שעליי לענות עליהן.

## 1. הירשמו ל־Apple Developer Program

👤 YOU

היכנסו עם Apple Account שמוגן באימות דו־שלבי, בחרו חשבון אישי או ארגוני (ארגון דורש מספר D-U-N-S) ושלמו את הדמים השנתיים. האפליקציה תופיע בחנות תחת השם שבו נרשמתם.

Done when: החברות ב־Apple Developer Program פעילה.

## 2. בנו בענן, בלי צורך ב־Mac

🤝 BOTH

EAS נכנס לחשבון Apple שלכם, יוצר תעודות ופרופילים ואז בונה על חומרה של Apple. (הגדרת ios.infoPlist.ITSAppUsesNonExemptEncryption ל־false ב־app.json אם האפליקציה משתמשת רק ב־HTTPS רגיל חוסכת את שאלת הייצוא והצפנה של Apple בכל בנייה.) בקשו מה־AI לאמת את ההגדרות קודם; את הבנייה עצמה, שדורשת כניסה לחשבון, הריצו בעצמכם.

Task: בדקו את app.json/app.config ואת eas.json עבור בנייה לסביבת ייצור ב־App Store. בדקו bundle ID, מספר בנייה, הרשאות, הצהרת הצפנה (ITSAppUsesNonExemptEncryption), אייקונים ופרופיל production. הציעו רק עריכות נדרשות; אל תריצו EAS ואל תיגשו לחשבון.

```
npm install -g eas-cli
eas login
eas build:configure
eas build --platform ios --profile production
```

Done when: אימתתם את ההגדרות, והבנייה בענן של המשתמשים הסתיימה בהצלחה.

## 3. צרו רשומת אפליקציה ב־App Store Connect

👤 YOU

My Apps → + → New App: פלטפורמה, שם (חייב להיות ייחודי בחנות), שפה, bundle ID (בחרו את ה־bundle ID ששלב 2 רשם, זהה לזה שב־app.json) ו־SKU לבחירתכם.

Done when: רשומת האפליקציה קיימת ב־App Store Connect עם אותו bundle ID כמו בפרויקט.

## 4. העלו את גרסת הבנייה

👤 YOU

גרסת הבנייה תופיע ב־App Store Connect אחרי ש־Apple מסיימת לעבד אותה, בדרך כלל תוך שעה.

```
eas submit --platform ios
```

Done when: גרסת הבנייה מופיעה כמעובדת (processed) ב־App Store Connect.

## 5. בדקו עם TestFlight

👤 YOU

הוסיפו מיד את עצמכם ועד 100 אנשים מהצוות כבודקים פנימיים. בודקים חיצוניים (באימייל או בקישור ציבורי) עוברים קודם בדיקת בטא קצרה. התקינו את TestFlight בטלפון והריצו את הבנייה האמיתית.

Done when: המשתמשים התקינו את הבנייה דרך TestFlight בטלפון אמיתי והמסלול המרכזי עובד.

## 6. מלאו את עמוד החנות ופרטי הפרטיות

🤝 BOTH

בקשו מה־AI לנסח תיאור ומילות מפתח לפי תכונות אמיתיות, ולמפות איזה מידע האפליקציה אוספת לפי הקוד וה־SDK. צילומי מסך, כתובות, דירוג גיל ותשובות סופיות ל־App Privacy הם עליכם, אחרי שבדקתם אותם.

Task: נסחו תיאור ומילות מפתח ל־App Store לפי תכונות מאומתות בלבד. אחר כך צרו רשימת שאלות פרטיות נפרדת מהקוד ומהתלויות, עם ראיות וסימון אי־ודאות במקום ניחושים.

Done when: התיאור, מילות המפתח, צילומי המסך, הכתובות, דירוג הגיל והתשובות ב־App Privacy מולאו ונבדקו על ידי המשתמשים.

## 7. התכוננו ל־App Review

🤝 BOTH

אם יש כניסה לחשבון, תנו לבודקים חשבון הדגמה. בקשו מה־AI לבדוק סיבות נפוצות לדחייה (קריסות, תוכן דמה, מעטפת דלה לאתר, היעדר מחיקת חשבון), ואז בדקו כל ממצא בעצמכם. קראו את ההנחיות העדכניות לפני ההגשה.

Task: בדקו באפליקציה חסמים נפוצים לאישור ב־App Review. בדקו כניסה לחשבון, מחיקת חשבון, תוכן דמה, קישורים שבורים, הרשאות והתנהגות של מעטפת אתר. החזירו רשימה לפי עדיפות, עם נתיבי קבצים ובדיקות ידניות.

Done when: כל חסם לבדיקה ברשימה תוקן או נבדק על ידי המשתמשים, וחשבון הדגמה מוכן אם יש כניסה לחשבון.

## 8. הגישו ופרסמו

👤 YOU

הוסיפו את הבנייה לגרסה ולחצו Submit for Review. בחרו אם לפרסם אוטומטית אחרי האישור או ידנית. אם נדחיתם, ההודעה ב־Resolution Center אומרת על איזו הנחיה; תקנו והגישו שוב.

Done when: הגרסה הוגשה לבדיקה, או אושרה ופורסמה.

## סיימו כל סשן עם דוח מצב (status report)

| # | שלב | מי | סטטוס |
|---|-----|----|-------|

הסטטוס הוא הושלם (Done), בתהליך (In progress), ממתין לכם (Waiting on you) או טרם התחיל (Not started). מתחת לטבלה: השלב הבא ובדיוק מה על המשתמשים לעשות בו, ואז כל מה שחסום ולמה.
