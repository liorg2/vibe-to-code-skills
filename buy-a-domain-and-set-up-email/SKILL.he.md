# רכשו דומיין והגדירו עליו אימייל

מאת Vibe to Dev (https://www.vibetodev.com/he). המדריך עם קישורים רשמיים: https://www.vibetodev.com/he/guides/buy-a-domain-and-set-up-email
זמן: שעה, ועוד עד יום להפצת DNS. עלות: כ־10–20 דולר לשנה עבור .com; אימייל מחינם (העברה) ועד כמה דולרים בחודש לכל תיבה.

שמות המוצרים ב־skill הזה (ספקי אירוח, מסדי נתונים, תשלומים, אימייל, מעקב שגיאות וכלי AI) הם דוגמאות בלבד. קודם בדקו במה הפרויקט באמת משתמש, לפי הקוד, קובצי ההגדרות וקובצי החבילות, והתאימו כל שלב למה שקיים בו. אם שלב מזכיר כלי שהפרויקט לא משתמש בו, בצעו את השלב המקביל בכלי שבו כן משתמשים; אם המשתמשים עוד לא בחרו כלי, הציגו את האפשרויות ותנו להם לבחור. ה־skill הזה עובד בכל סוכן פיתוח ב־AI (Claude Code, Cursor, Codex, Copilot ואחרים). אם מוזכרת פקודה, תיקייה או קובץ של כלי מסוים, השתמשו במקבילה של הסוכן שלכם.

## Rules

- בדקו קודם, הסבירו בשפה פשוטה, שלב אחד בכל פעם. אל תעברו לשלב הבא עד שתנאי "Done when" של השלב הנוכחי מתקיים.
- לעולם אל תיצרו משאבים בתשלום, אל תעשו push, אל תפרסו ואל תגישו בלי לבקש אישור. המשתמשים מבצעים בעצמם כל פעולה בחשבון, כל תשלום וכל לחיצה סופית על פרסום.
- כל שלב מסומן:
  - 👤 YOU: רק המשתמשים יכולים לבצע זאת (חשבון, תשלום, אימות זהות או לוח בקרה). הסבירו והמתינו.
  - 🤖 AI: אתם מבצעים זאת בפרויקט, במסגרת הכללים שלמעלה.
  - 🤝 BOTH: אתם מכינים או בודקים; המשתמשים מבצעים את החלק של החשבון או הפרסום.
- בתיאורי השלבים הפנייה היא למשתמשים; בשורות "Task:" הכוונה ב־"אני" או "עליי" היא למשתמשים: דווחו להם.

## Custom domain settings by host

אל תניחו שמשתמשים ב־Vercel. קודם בדקו באיזה ספק אירוח הפרויקט באמת משתמש לפי קובצי ההגדרות או כותרות התגובה, או שאלו את המשתמשים:

| ספק אירוח | איפה מוסיפים דומיין מותאם אישית |
|---|---|
| Vercel | Project → Settings → Domains |
| Netlify | Site configuration → Domain management |
| Cloudflare Pages / Workers | לשונית Custom domains בפרויקט ה־Pages או ה־Worker |
| Render, Railway, Fly.io | Render: Settings → Custom Domains. Railway: Service → Settings → Networking. Fly: `fly certs add` |

## Redact

## איך לדבר

- קצר, ידידותי ומקצועי. משפטים קצרים ומילים פשוטות. בלי מילות מילוי, בלי מחמאות ובלי לחזור על מה שהמשתמשים אמרו הרגע.
- בכל הודעה: מה מצאתם או עשיתם, ואז הדבר האחד שהמשתמשים צריכים לעשות או להחליט. פרטים רק אם ביקשו.
- שאלו רק מה שאי אפשר למצוא בפרויקט בעצמכם. שאלה אחת בכל פעם, עם הניחוש הטוב ביותר שלכם כתשובת ברירת מחדל.
- ענו על מה שנשאלתם, ועצרו.

## Start

עזרו לי לחבר דומיין ואימייל לפרויקט. עברו על המאגר וזהו את ספק האירוח הנוכחי, כתובת סביבת הייצור, הקוד שקשור לאימייל וכל הנחה קיימת על הדומיין. אל תקנו דבר, אל תיכנסו לחשבונות ואל תשנו DNS. תנו לי רשימה שלא תלויה בספק מסוים ואמרו בדיוק מה עליי לאמת ידנית.

## 1. בחרו שם

🤝 BOTH

קצר, קל להגיד בקול, בלי מקפים. עדיף .com, או סיומת של המדינה אם הלקוחות מקומיים. בקשו מה־AI להציע מועמדים ולתפוס איות מבלבל, ואז בדקו בעצמכם זמינות וסימני מסחר.

Task: הציעו 20 שמות דומיין קצרים למוצר לפי ה־README והקהל שלו. הימנעו ממקפים וממילים שקשה לאיית. קבצו לפי רעיון השם וסמנו אפשרות לבלבול; אל תטענו שאף שם זמין.

Done when: המשתמשים בחרו שם ובדקו שהוא פנוי ואינו סימן מסחר של מישהו אחר.

## 2. רכשו אצל רשם דומיינים

👤 YOU

Cloudflare Registrar מוכר במחיר עלות, בלי תוספת; גם Namecheap ו־Porkbun פופולריים. השוו את מחיר החידוש, לא את מחיר השנה הראשונה. הפעילו חידוש אוטומטי, פרטיות WHOIS (בדרך כלל בחינם) ואימות דו־שלבי בחשבון הרשם: מי שמחזיק בכניסה הזאת הוא הבעלים של הדומיין שלכם. יש מלכודת אחת: דומיין שנקנה ב־Cloudflare חייב להישאר עם DNS של Cloudflare, ולכן בשלב הבא מוסיפים שם רשומות במקום להחליף nameservers.

Done when: הדומיין נרכש, עם חידוש אוטומטי, פרטיות WHOIS ואימות דו־שלבי פעילים.

## 3. הפנו את הדומיין לאתר

🤝 BOTH

אצל ספק האירוח (ב־Vercel: Project → Settings → Domains) הוסיפו את yourname.com ואת www.yourname.com. שם תראו את רשומות ה־DNS המדויקות שצריך ליצור אצל הרשם. (אם ה־DNS שלכם ב־Cloudflare, הגדירו את הרשומות כ־"DNS only" / ענן אפור בזמן שספק האירוח מאמת את הדומיין ומנפיק תעודה.) תנו ל־AI את שמות וסוגי הרשומות (אף פעם לא את פרטי הכניסה לחשבון) ובקשו שיבדוק אותן לפני השמירה. תעודת HTTPS מונפקת ברגע ש־DNS פעיל.

Task: סקרו את רשימת רשומות ה־DNS המוצעת: התנגשויות, כפילויות וטעויות נפוצות. הסבירו מה כל רשומה עושה. אל תמציאו ערכים חסרים; סמנו מה עליי להעתיק מספק האירוח.

Done when: גם הדומיין הראשי וגם www טוענים את האתר ב־HTTPS.

## 4. החליטו איזה אימייל דרוש

👤 YOU

רק מקבלים מייל? העברה חינמית (Cloudflare Email Routing, שדורשת DNS ב־Cloudflare, או שירות ההעברה של הרשם) שולחת את hello@yourname.com ל־Gmail שכבר יש לכם. צריכים תיבות אמיתיות שגם שולחות? Google Workspace או Zoho Mail. בחרו ספק אחד: לדומיין צריך להיות סט אחד של רשומות MX.

Done when: המשתמשים בחרו בין העברה לבין תיבות אמיתיות, ובחרו ספק אחד.

## 5. אמתו את הדומיין והוסיפו רשומות MX

👤 YOU

ספק האימייל נותן לכם רשומת TXT שמוכיחה שהדומיין שלכם, ורשומות MX שמנתבות אליו דואר נכנס. הוסיפו אותן בדיוק כמו שהן מוצגות, אצל מי שמנהל את ה־DNS, ואז לחצו על אימות אצל הספק.

Done when: הספק מציג שהדומיין מאומת ורשומות ה־MX מוגדרות ב־DNS.

## 6. הוסיפו SPF, DKIM ו־DMARC כדי לא להגיע לספאם

🤝 BOTH

SPF מפרט מי מורשה לשלוח בשם הדומיין (רשומת SPF אחת בלבד; אם יש שתיים, מאחדים אותן). DKIM הוא מפתח חתימה שהספק יוצר. DMARC אומר לנמענים מה לעשות כשהבדיקות נכשלות; התחילו בניטור בלבד. בקשו מה־AI לעבור על הרשומות, אבל את הערכים המדויקים של הספק העתיקו בעצמכם.

Task: בדקו את רשומות SPF, DKIM ו־DMARC האלה לשגיאות תחביר וכפילויות. הסבירו כל שינוי. אל תחליפו ערכים ייחודיים לספק בניחושים.

```
TXT  @        v=spf1 include:_spf.google.com ~all      (Google example)
TXT  google._domainkey   v=DKIM1; k=rsa; p=…  (copy from the admin console)
TXT  _dmarc   v=DMARC1; p=none; rua=mailto:you@yourname.com
```

Done when: קיימות רשומת SPF אחת בדיוק, רשומת DKIM ורשומת DMARC עם הערכים המדויקים של הספק.

## 7. בדקו את התוצאה

👤 YOU

אם הגדרתם תיבת דואר מלאה או שירות שליחה מהאפליקציה, שלחו הודעה לכתובת Gmail, פתחו אותה, בחרו Show original וחפשו SPF: PASS, DKIM: PASS ו־DMARC: PASS. האתר mail-tester.com נותן ציון ומסביר מה חסר. אם הגדרתם רק העברה חינמית, שלחו אימייל מכתובת אחרת אל hello@yourname.com וודאו שהוא מגיע לתיבה.

Done when: אימייל בדיקה ל־Gmail מציג SPF, DKIM ו־DMARC במצב PASS (או, בהעברה בלבד, אימייל בדיקה נכנס מגיע לתיבה).

## 8. אימייל מהאפליקציה הוא שירות נפרד

🤝 BOTH

איפוסי סיסמה וקבלות שהאפליקציה שולחת צריכים לעבור דרך שירות שליחה (Resend, Postmark), בתת־דומיין כמו mail.yourname.com ועם רשומות SPF ו־DKIM משלו. ככה בעיה בשליחה המונית לא תפגע בתיבה האישית שלכם.

Done when: דלגו אם האפליקציה לא שולחת אימייל; אחרת אימייל מהאפליקציה עובר דרך שירות שליחה בתת־דומיין עם SPF ו־DKIM משלו.
